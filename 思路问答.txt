量化回测项目：思路问答
整理日期：2026-11-07

1. 问：这个项目最终要做什么？
答：用沪深 300 当前成分股和 2020-2025 年日频数据，计算 BP、MOM20、VOL60，完成 Rank IC/IR、G1-G5 分层、G5-G1 多空和等权合成分，并写出可复现报告。报告中必须说明数据偏差和局限性。

2. 问：要不要一次性完成整个交付闭环？
答：不采用这种方式。按阶段学习，每完成一个阶段先检查数据和理解原理，再进入下一阶段。

3. 问：Baostock 获取数据免费吗？
答：个人学习和回测通常免费，不需要账号或 API Key。公开大量原始数据或商业使用前，需要另外核对数据使用条款。

4. 问：回测框架用 Backtesting.py 还是 Backtrader？
答：本项目主流程使用 Pandas 做分层和组合回测；Backtesting.py 用于环境验证和入门示例。暂时不同时深入学习 Backtrader。

5. 问：已有 Python 虚拟环境能否直接使用？
答：技术上可以，但不同项目最好使用独立环境。本项目使用 D:\回测项目\.venv，便于固定依赖和复现。

6. 问：最初 14-20 个工作日、每天 10-12 小时的计划适合当前学习速度吗？
答：原计划偏紧。建议按每周约 12-15 小时执行，年底前优先完成核心流程，历史成分股、交易成本和更复杂的撮合放到后续。

7. 问：为什么只下载一只股票还不能开始因子回测？
答：IC、横截面排名和分组都需要同一天的多个股票。单只股票只能练习接口和清洗，不能完成横截面研究。

8. 问：为什么要把五只股票拼成一个表？
答：每只股票单独保存便于增量下载；拼成以 (date, code) 为键的长表后，才能按交易日计算排名、Z-score、IC 和组合收益。

9. 问：五只股票试点通过后下一步做什么？
答：先确认全部为前复权、字段类型和日期正确，再加入沪深 300 指数与质量报告；通过后扩展到 300 只股票，之后才计算因子。

10. 问：这个项目目前最大的数据局限是什么？
答：使用当前沪深 300 名单回看历史会产生幸存者偏差。项目先预留历史成分股接口，并在 README 和报告中明确说明。

11. 问：个股 stock_return 和指数 index_return 有什么区别？
答：算法完全相同，都是“期末价 / 首日价 - 1”，区别在被除的口径。个股用前复权收盘价，已剔除分红送股的跳空，近似含息收益；上证指数是价格指数，不含成分股现金分红。两边不是同一把尺子，对比图和报告中必须注明口径。

12. 问：做个股与指数对比时，要不要把 adjustflag 统一成 "3"？
答：不要。指数没有复权概念，adjustflag 传 1、2、3 返回结果完全一致（实测首末值均为 3116.5119 / 2974.9348），统一成 3 对指数是空操作。对个股，不复权会把分红除权记成下跌，系统性低估收益。

13. 问：前复权、后复权、不复权，算收益率时区别大吗？
答：前复权（"2"）与后复权（"1"）只差一个常数倍数（2023 年浦发：82.6709 对 6.1847），收益率序列完全等价，实测最大差 1e-6，属浮点误差。不复权（"3"）的差别是实质性的：2023 年浦发全年 -8.44%，前复权 -4.31%，少算 4.13 个百分点，差额全部来自 2023-07-21 分红除权（当日不复权 -4.04%，前复权 +0.28%）。

14. 问：既然不复权会低估收益，为什么还可以用 "3" 存库？
答：因为 Baostock 已经把除权修正做在 preclose 上。实测 2023-07-21：close 7.12、preclose 7.10（前一交易日收盘 7.42 减掉 0.32 元分红）、pctChg +0.28%，是真实涨幅。所以原始价可以存 "3"（原始值可复现），但计算累计收益必须用 pctChg 连乘，不能用 close / close[0]。

15. 问：前复权价格适合存库吗？
答：不适合。前复权以查询当天的最新价为基准向前推算，同一段历史在不同日期拉取数值会变（比值不变）。要落盘存档、保证可复现，应存后复权（"1"）或不复权原始值（"3"），作图时再按需转换。

16. 问：累计收益率序列有什么要特别注意的？
答：对起点极敏感，基准日两端必须一致。merge(how="inner") 能保证两条曲线从同一交易日出发；合并后建议显式 sort_values("date")，不要依赖合并顺序隐含的排序。

17. 问：用当前沪深 300 成分股回看 2020 年历史，有什么问题？
答：这是幸存者偏差（前视偏差）。当前名单只包含“活到今天并入选”的股票，回溯回测会系统性高估收益，是这类管道最典型的致命伤。需要换成历史成分股，或用全市场股票池并按当时的上市、退市状态过滤，至少在报告和 README 中明确说明。

18. 问：这个项目按什么节奏推进比较合理？
答：先把 5 只股票的完整链路跑通（原始 parquet -> 清洗 -> 合并长表 -> 基础统计），确认字段类型、日期、复权口径都正确，再扩展到 300 只，最后才做因子和分层回测。不要一次性写完整个闭环。
